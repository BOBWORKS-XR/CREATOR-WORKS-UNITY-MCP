# Creator Works MCP 2.7.1

Windows hotfix for updates blocked by lingering private Node processes.

- MCP exits when its AI client disconnects, including during a pending Unity
  compile wait. Already-dispatched Unity work is not cancelled or sent twice.
- A blocked standalone installer offers **Yes: disconnect**, **No: recheck**,
  or **Cancel**. It targets only this installation's verified private runtimes.
- **Creator Hub 0.1.3 or newer** provides the same confirmed disconnect before
  updating MCP. Update Hub first, or use this standalone Windows installer.
- Other Node processes, AI applications, settings and Unity projects are not
  force-closed or removed. If a client reconnects, pause its MCP connection and
  retry. There is no repeated process-kill loop.

## Upgrade

Save ongoing work. Run `Creator.Works.MCP_2.7.1_x64-setup.exe`, or use Update app
in Hub 0.1.3 or newer. Approve disconnect only when ready to stop the active MCP
connections. Reconnect your AI client after the update. Do not uninstall, delete
app data, or close every Node process in Task Manager.

## Verification

The exact installer passed upgrades from **2.6.0, 2.7.0-alpha.1,
2.7.0-alpha.2 and 2.7.0** on disposable Windows runners. Tests cover two active
private runtimes, refusal without consent, scoped cleanup, unrelated-process
preservation, settings/content preservation, installed payload hashes, EOF during
idle and pending work, connected usability, and busy uninstall refusal.
