# Creator Works MCP 2.6.0-rc.1

**Prerelease for testing.** Stable users can stay on
[2.5.1](https://github.com/BOBWORKS-XR/CREATOR-WORKS-UNITY-MCP/releases/tag/v2.5.1).
This candidate focuses on token efficiency, accurate scene inspection, and
Editor reload handling, with multiplatform packaging and test-run controls.

## Expected Benefits

- **Less initial AI context:** new configurations use the 24-tool core profile instead of all 52 tools. Measured schema text is 21,827 versus 47,268 UTF-8 bytes, about 54% smaller. This is not a 54% reduction in total tokens, cost, or account usage.
- **Read the relevant documentation, not the entire library:** `get_mcp_reference` searches local manual, component, JavaScript, and workflow entries, including corrections and continuation details. Full documents remain available explicitly. No paid retrieval service, embeddings database, or new runtime dependency is required.
- **Avoid oversized replies:** hierarchy, component, console, import, compiler, and prefab reads default to a 64 KiB compact response-text budget. Counts, omissions, errors, and freshness remain visible; callers can filter or explicitly raise the budget up to 4 MiB.
- **Keep all capabilities when needed:** Full retains all 52 tools and benefits from focused references and bounded reads. Smaller profiles hide specialist tools until the profile is changed and the client reconnects. Existing saved Full selections are preserved.
- **Reduce avoidable inspection/retry loops:** request identity-only component inventories and selected properties, wait through Editor reloads, and resume pending commands using their exact project-bound polling instructions.

## Scene and Editor Reliability

- `componentDetails: "identity"` avoids serializing component properties. Field-only and filtered fresh reads use targeted queries rather than a full state export.
- Missing requested properties are reported as `missingProperties`, not mistaken for false. Fresh queries support hidden/nested serialized paths and bounded renderer enabled/material summaries.
- Compile waits tolerate domain reload within the caller's deadline and require a fresh, settled Editor. Stale diagnostics alone cannot report successful readiness.
- Menu/query timeouts retain command and project identity plus polling arguments. A timeout does not cancel an operation; do not resubmit a pending mutation.
- Automatic full-scene exporting remains disabled by default in Edit and Play mode. Explicit refresh still works; Unity object access remains on the main thread.

## Launcher and Packaging

- Optional restriction on unfiltered Unity test runs. The default remains permissive for compatibility; the Unity policy is project-scoped and survives domain reload.
- Launcher, CLI, and PowerShell setup preserve existing setting fields. Malformed settings fail without being replaced, and the UI reports persistence failures.
- Packages: Windows x64 setup EXE; Linux x86_64 AppImage, DEB, and RPM; macOS Apple Silicon DMG; and a standalone Node.js 20+ ZIP.
- Launcher packages include a private Node.js 24 LTS runtime. The standalone ZIP requires your own Node.js and includes Windows and Unix setup entry points.
- Release checksums use the actual uploaded filenames and reject missing platforms, incomplete uploads, or invalid digests.

## Upgrading and Testing

1. Back up your Unity project and client configuration. Save and close the projects whose bridges you plan to update.
2. Install the matching package. On Windows, close Creator Works MCP and MCP clients if Setup reports that its private runtime is in use; Setup does not force-close them.
3. Check imported projects and your selected tool profile. Existing Full configurations stay Full; new ones default to Token Saver. Use Full or a specialist profile for graph authoring and testing.
4. Use **Update Bridges** for the projects you intend to test, reopen Unity, and let it compile. Installing the launcher alone does not prove a project bridge was refreshed.
5. Reconnect the MCP client, call `get_bridge_status`, and verify the project identity, candidate bridge version, and fresh readiness before editing.
6. Try your normal scene and graph tasks. Check missing-property diagnostics, compile/reload recovery, pending-command polling, and Editor responsiveness. Report the version, profile, SDK, reproduction, and observed result without sharing credentials or private project content.

**Unsigned distribution:** the Windows EXE is unsigned and the macOS app is not
notarized, so OS security warnings are expected. Compare your download with
`SHA256SUMS.txt`. A checksum verifies integrity, not publisher identity.

## Verification and Limits

- Local candidate checks passed: **182 Node tests**, **21 Rust launcher tests**, version synchronization, standalone protocol/reference and archive smoke tests, Windows NSIS build, and zero reported npm audit vulnerabilities.
- The bridge passed compile/command fixtures in disposable Unity **2022.3.39f1** and **6000.3.21f1** projects. These exercised targeted property reads, no full-snapshot rewrites for those queries, and isolated test-policy persistence/guard behavior. The policy check is not a full Test Runner execution.
- [GitHub Actions](https://github.com/BOBWORKS-XR/CREATOR-WORKS-UNITY-MCP/actions) records the combined candidate's CI and packaging checks. Building a package is not proof of clean installation or everyday operation on that platform.
- Candidate clean-install/upgrade, real-project tasks, large-project performance, and end-to-end token/latency measurements remain acceptance work before stable release. Earlier local test builds are not evidence that this exact candidate was installed.
- Shader Graph mutation is experimental. Hosted loading, headset interaction/performance, and multiplayer need real-client testing; Editor/build checks cannot confirm them.
